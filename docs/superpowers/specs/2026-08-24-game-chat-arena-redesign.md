# 对局竞技区与本局消息设计

## 目标

- iPhone 进入对局后，无需滚动即可看到竞技区、观战成员和底部操作。
- 压缩顶部品牌、对局标题、统计信息所占高度，把主要空间留给纵向椭圆德州牌桌。
- 在现有“竞技区、购买记录”之外增加“消息区”。
- 提供最小可用的本局文字消息：能查看、能发言、竞技区能看到最新一句。

## 明确不做

- 不修改 Prisma Schema，不创建数据库表，不生成数据库迁移。
- 不持久化消息，不提供跨局历史消息。
- 不做未读数字、推送通知、正在输入、撤回、编辑、图片、表情、回复、搜索或复杂管理功能。
- 不为多 API 实例设计共享缓存；当前单 API 容器部署使用进程内存即可。

## 页面布局

### 顶部

- 品牌、问候和退出压缩为一行。
- 对局名称与“进行中”状态压缩为一行。
- 页签固定为“竞技区、购买记录、消息区”。
- 玩家数、总买入、每手金额和开局时长使用单行四列紧凑展示。
- 观战成员使用单行头像条，始终位于牌桌上方，避免被底部操作栏遮挡。

### 竞技区

- 使用纵向椭圆德州牌桌，占据顶部信息和底部操作之间的剩余空间。
- 牌桌包含木质外沿、绿色桌布、投注线、公共牌位和座位标记，保持现有深色金色风格。
- 玩家头像沿椭圆边缘排列；头像、昵称和当前手数保持可读。
- 竞技区只显示全场最新的一条消息，并把气泡定位在发送者头像附近，避免多个气泡同时遮挡牌桌。
- 空桌时仍使用同一竞技区高度，但牌桌内部显示“等待玩家入座”，不再留下大块无意义空白。

### 消息区与发言

- 消息区按时间顺序展示当前牌局内存中的消息，包含头像、昵称、内容和相对时间。
- 不显示未读数量。
- 底部保留“购买筹码”和“发言”两个按钮，并使用 iPhone `safe-area-inset-bottom` 留出安全距离。
- 点击“发言”打开底部小浮层，仅包含输入框、发送和关闭。
- 发送成功后关闭浮层；发送失败时保留输入内容并显示可重试提示。

## 消息数据与接口

### 数据结构

每条消息只包含：

- `id`
- `gameId`
- `userId`
- `nickname`
- `avatarUrl`
- `text`
- `createdAt`

API 进程维护 `Map<gameId, GameMessage[]>`。每局最多保留最近 50 条，超过后丢弃最早消息，避免长时间牌局无限占用内存。

### 规则

- 所有已登录且有权查看当前对局的用户，包括玩家和观战成员，都可以发言。
- 只有 `ACTIVE` 状态允许发送消息。
- 文本去除首尾空白后必须为 1～120 个字符；不接收控制字符。
- 服务重启后消息自然清空，这是预期行为。
- 对局进入 `SETTLING`、作废或被硬删除时立即清空对应内存消息。

### 通信方式

- `GET /api/games/:id/messages`：读取当前内存消息。
- `POST /api/games/:id/messages`：发送一条消息。
- 发送成功后，通过现有对局 Socket 房间广播 `game.message.created`。
- 页面首次进入时读取消息；Socket 正常时接收实时消息；实时连接中断时，跟随现有每 10 秒同步补拉消息列表。
- 不把消息加入数据库对局快照，避免影响结算、历史、备份和恢复数据结构。

## 清理时机

- `ACTIVE → SETTLING` 成功提交后清空。
- `ACTIVE → VOIDED` 成功提交后清空。
- 超级管理员硬删除对局后清空。
- 清理只针对目标 `gameId`，不能影响其他正在进行的牌局。

## 错误处理

- 对局不存在或用户无查看权限时，沿用现有 `NOT_FOUND` / `FORBIDDEN`。
- 非进行中对局发送消息时返回 `GAME_STATE_CONFLICT`。
- 内容无效时返回 `VALIDATION_ERROR`。
- 客户端只显示中文提示，不展示服务端堆栈或原始异常。

## 验证范围

- 合同测试：消息请求、响应和 Socket 事件严格校验。
- API 单元测试：发送、读取、最多 50 条、不同牌局隔离、结算/作废/删除清理和权限检查。
- 实时测试：只向目标牌局中仍有权限的 Socket 广播。
- 页面测试：三个页签、发言浮层、发送成功/失败、实时新增、断线补拉和最新消息气泡定位。
- 移动端检查：至少覆盖 320px、现有 iPhone 截图宽度和 640px，确认竞技区、观战条与底部安全区不重叠。
